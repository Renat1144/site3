# Авторские туры

Премиальный WordPress-сайт об авторских путешествиях по Турции. Главная и восемь страниц туров, шапка и подвал собраны из блоков Gutenberg и редактируются через **Страницы** в обычной админке WordPress.

## Локальный запуск

Требуется установленный и запущенный Docker Desktop.

```sh
./local-setup.sh
```

После первого запуска скрипт автоматически создаст локальные пароли, установит WordPress и активирует тему.

- Сайт: http://localhost:8082/
- Админка: http://localhost:8082/wp-admin/
- Локальная тестовая почта: http://localhost:8026/
- Локальные данные для входа: `.local-admin.txt`

Файлы `.env`, `.local-admin.txt`, `wp-config.php`, база данных, загрузки WordPress и архивы переноса не публикуются в Git.

Подробности: [LOCAL_SETUP.md](LOCAL_SETUP.md).

## Редактирование страниц

- Главная: **Страницы → Главная**.
- Каждый тур находится в **Страницы** как отдельная опубликованная страница.
- Новые самостоятельные разделы сайта создаются через **Страницы → Добавить страницу**.
- Новая страница получает общую шапку и подвал, а также стартовую секцию в стиле сайта.
- Блоки не заблокированы: их можно добавлять, удалять, копировать и переставлять.
- «Внешний вид → Редактор» нужен только для технической настройки шаблонов и общих частей темы.

## Форма связи

- Содержание формы редактируется блоком **«Форма связи»** на странице **Главная**.
- Адрес получателя задаётся в **Настройки → Форма связи** и хранится только в базе WordPress.
- В локальной среде письма перехватывает Mailpit на `http://localhost:8026/`; наружу они не отправляются.
- На реальном хостинге потребуется один раз настроить SMTP хостинга или почтового ящика домена. Пароль SMTP нельзя добавлять в Git.
- Статический GitHub Pages экспорт не содержит серверную форму WordPress, но сохраняет CTA-кнопки: на статических страницах они ведут в контактный раздел главной.

## Статическая версия для GitHub Pages

После изменений в WordPress обновите статический снимок:

```sh
./script-static-export.sh
```

Скрипт создаёт корневой `index.html` и восемь снимков в `static-pages/`. При публикации GitHub Actions раскладывает страницы туров по адресам вида `/mesopotamiya/`, а WordPress продолжает работать локально и остаётся главным источником редактируемого контента.

При запуске `FINISH_WORK.command` или `FINISH_WORK.cmd` статический снимок обновляется автоматически перед созданием приватного архива переноса.

## Перенос между устройствами

Кнопка **FINISH_WORK** создаёт приватный архив версии 2. В него входят:

- база WordPress, настройки пользователей и страниц;
- `uploads` и локальная конфигурация;
- актуальные файлы темы и статического сайта;
- Docker-конфигурация и документация;
- все скрипты `import`, `export`, статического экспорта;
- кнопки **START_WORK** и **FINISH_WORK** для macOS и Windows.
- `PROJECT_HANDOFF.md` с актуальным контекстом работы и техническим журналом завершения.

Кнопка **START_WORK** восстанавливает и данные WordPress, и файлы проекта. Старые архивы версии 1 без снимка файлов также поддерживаются. Папки `.git`, `backups`, ядро WordPress и другие игнорируемые или генерируемые файлы не вкладываются повторно.

Codex обязан читать `PROJECT_HANDOFF.md` в начале работы и самостоятельно обновлять его смысловую часть после каждой задачи, изменяющей проект. При нажатии **FINISH_WORK** в этот файл дополнительно записываются дата, платформа, commit, список изменённых файлов и состояние Docker без содержимого секретных файлов.
