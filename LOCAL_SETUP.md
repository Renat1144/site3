# Локальный WordPress

## Адреса

- Сайт: http://localhost:8082/
- Админка: http://localhost:8082/wp-admin/
- Тестовая почта: http://localhost:8026/
- Логин и пароль: `.local-admin.txt`

## Управление

Из папки `wordpress_site3`:

```sh
./local-setup.sh
```

Команда создаёт локальную конфигурацию при первом запуске, запускает контейнеры, устанавливает WordPress и активирует тему `Turkey Signature`. Повторный запуск безопасен и не переустанавливает сайт.

Остановить сайт без удаления данных:

```sh
docker compose stop
```

Снова запустить:

```sh
docker compose up -d db wordpress
```

Проверить состояние:

```sh
docker compose ps
```

Данные MariaDB находятся в отдельном Docker-томе `wordpress_site3_db_data`. Не удаляйте этот том, если хотите сохранить изменения, сделанные через WordPress.

## Редактирование

После входа откройте **Страницы → Главная** или одну из восьми страниц туров. В редакторе отображаются реальные блоки публичной страницы, включая общую шапку и подвал. Тексты, изображения, ссылки, кнопки, секции и их порядок можно менять визуально.

Новые самостоятельные разделы сайта создавайте через **Страницы → Добавить страницу**. WordPress автоматически добавит общую шапку, стартовую секцию в стиле сайта и подвал. Шаблон не заблокирован: блоки можно добавлять, удалять, копировать и перемещать.

Раздел **Внешний вид → Редактор** оставлен для технической настройки файловых шаблонов и общих частей темы; для повседневной работы с содержимым он не требуется.

Форма заявки находится на главной как блок **«Форма связи»**. Её заголовки, подписи полей, кнопка, текст согласия и сообщения после отправки редактируются в правой панели Gutenberg. Получатель заявок задаётся отдельно в **Настройки → Форма связи** и хранится в базе WordPress.

Локально письма не уходят во внешний интернет: сервис Mailpit принимает их внутри Docker и показывает на `http://localhost:8026/`. Это позволяет проверить полный сценарий формы без почтового пароля.

На будущем хостинге нужно подключить SMTP почтового ящика домена или SMTP-плагин хостинга, указать защищённые учётные данные вне Git и отправить тестовое письмо. При отсутствии локальной переменной `TS_MAIL_HOST` плагин использует обычный `wp_mail()`, поэтому код формы менять не потребуется.

## Обновление GitHub Pages

WordPress остаётся редактируемой версией сайта. Для GitHub Pages из его текущей публичной страницы создаётся статический снимок:

```sh
./script-static-export.sh
```

В Windows используйте:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\script-static-export.ps1
```

Команда обновляет `index.html`, `.nojekyll` и восемь снимков страниц туров в `static-pages/`. GitHub Actions при публикации переносит эти снимки в корень артефакта, поэтому ссылки карточек сохраняют красивые адреса. Локальные пароли, база и `wp-config.php` в статические страницы не включаются. Кнопки, разметка, стили и JavaScript серверной формы также намеренно исключаются из GitHub Pages.

Скрипты `FINISH_WORK.command` и `FINISH_WORK.cmd` выполняют этот шаг автоматически перед приватным экспортом базы и uploads.

## Что переносится через Google Drive

Новый приватный архив переноса версии 2 содержит базу, `uploads`, локальные настройки и полный снимок рабочих файлов проекта. В снимок входят тема, статический `index.html`, Docker-конфигурация, документация, import/export-скрипты и кнопки **START_WORK** / **FINISH_WORK** для macOS и Windows.

При импорте файлы из снимка безопасно обновляются в папке проекта без массового удаления других файлов. После этого восстанавливаются загрузки и база WordPress. Архивы прежней версии 1 продолжают импортироваться, но в них нет снимка файлов проекта.

Файл `PROJECT_HANDOFF.md` передаётся в том же архиве. Codex обновляет в нём смысловое состояние проекта после выполненных задач, а кнопка **FINISH_WORK** автоматически дописывает дату, Git-состояние и состояние Docker. Секреты и содержимое закрытых конфигурационных файлов в этот журнал не записываются.

Архив содержит базу, локальные учётные данные и другие секреты. Храните его только в закрытом Google Drive и никогда не добавляйте в GitHub.
