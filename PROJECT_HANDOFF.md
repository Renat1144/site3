# Передача контекста проекта Turkey Signature

Этот файл хранит актуальное состояние проекта для продолжения работы в новой сессии или на другом устройстве. Смысловую часть обновляет Codex после каждой задачи, изменяющей проект. Кнопка **FINISH_WORK** дописывает внизу безопасный технический снимок.

Не добавлять сюда пароли, токены, содержимое `.env`, `wp-config.php`, дампы базы и персональные данные.

- На Windows точно сопоставлены Docker-проекты: сайт `8080` использует `wordpress_wordpress_db`, а `wordpress_site3` на `8082` использует `wordpress_site3_db_data`.
- Только старый том `wordpress_site3_db_data` заменён новым томом Compose-проекта `wordpress_site3`; проект, контейнеры, сеть, файлы и том сайта `8080` не изменялись.
- База, uploads и локальное состояние `wordpress_site3` восстановлены из проверенного архива версии 2 `wordpress_site3-transfer-01-08-2026_00-09.zip`.
- В PowerShell- и Bash-импорте исправлены вызовы WP-CLI: перед `search-replace`, `eval-file` и `rewrite` теперь явно вызывается команда `wp`.
- Windows-импорт извлекает имена ZIP как UTF-8 вручную с проверкой безопасных путей; рабочие кнопки теперь имеют одинаковые ASCII-имена **START_WORK** / **FINISH_WORK** на обеих платформах.
- Добавлен `.gitattributes`: Bash- и macOS-файлы закреплены за LF, PowerShell- и Windows CMD-файлы — за CRLF, чтобы перенос между платформами не ломал выполнение скриптов.
- Windows-экспорт и технический handoff теперь находят `git.exe` не только через `PATH`, но и в стандартной установке Git, Scoop, GitHub Desktop и runtime Codex. Это исправляет запуск кнопки **FINISH_WORK** двойным кликом, когда Git доступен Codex, но не системному PowerShell.
- Сбор списка файлов Windows-экспортом переведён на явное чтение UTF-8 из `git ls-files -z`; вместе с ASCII-именами **START_WORK** / **FINISH_WORK** это исключает зависимость кнопок от системной кодировки.
- Четыре запускаемых файла для macOS и Windows переименованы в `START_WORK.command`, `START_WORK.cmd`, `FINISH_WORK.command` и `FINISH_WORK.cmd`; обязательные проверки экспорта и документация синхронизированы с новыми именами.

### Важные решения и ограничения

- WordPress является главным редактируемым источником; статический `index.html` — снимок для GitHub Pages.
- Публичная страница и редактор Gutenberg должны оставаться единой реализацией и визуально совпадать.
- В GitHub нельзя добавлять закрытые архивы, `.env`, `wp-config.php`, локальные логины и дампы базы.
- Форма заявки пока остаётся обозначенным местом-заполнителем: адресат заявок и окончательный текст согласия не предоставлены.
- Сырой снимок заменённого тома сохранён в `backups/volume-snapshots/`; страховочный архив свежего состояния перед импортом сохранён в `backups/`. Оба каталога закрытые и не должны попадать в Git.
- Четыре дублирующих файла с искажёнными кириллическими именами, созданные старой распаковкой, сохранены для анализа в `backups/import-name-artifacts-20260801-0034/` и удалены из рабочего корня.
- Первый Windows-запуск прежней кнопки завершения 1 августа обновил `index.html` и добавил технический журнал, но остановился до создания нового приватного архива из-за недоступного в системном `PATH` Git; база и uploads не изменялись.
